The hardest thing: an operator surface that cannot be wrong

An access control dashboard is a real-time view of physical infrastructure. Doors change state from hardware, from other operators, and from schedules — all at once, all asynchronously. The naive version drifts out of sync within minutes, and a stale door state is worse than no state at all, because the operator trusts it.

The approach

Treat the UI as a projection of an event stream rather than a cache of REST responses: one authoritative reducer, optimistic updates that are explicitly reconciled, and a visible staleness indicator instead of a silent lie. Then make the component layer boring on purpose — a small set of primitives with tight APIs, so that the interesting complexity stays in one place where it can be reasoned about.

What I'm building now

Developer tooling for spec-driven, multi-agent delivery: taking a written specification and turning it into work that AI agents can execute in parallel across a service fleet, with machine-checkable gates deciding whether the result is allowed to ship.

The interesting problem isn't the model — it's the interface. Agents need context shaped for them, constraints they can't argue with, and a verification story a human can audit in under a minute. That is a frontend problem wearing a backend costume, which is why I like it.

This is work done at Genea. Described here at the level of craft, not architecture.
